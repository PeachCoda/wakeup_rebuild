# FakeUp 网页课表

FakeUp 是一个面向手机使用的杭电课表网页。项目目标是保留课表本体和少量高频操作，让课表打开快、信息密度高、导出分享方便。

## 功能

- 显示课表、切换教学周、显示或隐藏非本周课程
- 登录上课啦账号并同步课表
- 上课啦密令签到
- 自定义课表背景，支持缩放、位移和透明度调整
- 导出当前周课表图片
- PWA 安装到桌面

## 上课啦签到鉴权说明

FakeUp 的签到入口只是把上课啦签到流程收进课表页面里，并不绕过上课啦的鉴权。当前流程仍依赖官方登录态、官方验证码参数、定位参数和正式签到接口。

### 登录态

第一次使用签到或同步课表时，需要在 FakeUp 中登录上课啦账号。前端把学号和密码提交给本站后端 `/api/signin/account/login`，后端完成杭电 SSO / 上课啦登录流程，并保存后续刷新上课啦登录态所需的信息。

浏览器侧只保存本站自己的会话 Cookie 和学号提示，不保存上课啦密码。后端通过本站会话识别当前用户，并在需要同步课表或签到时刷新/获取上课啦 token。

### 课表同步

同步课表时，前端请求 `/api/signin/schedule/sync`。后端会先确认本站会话和上课啦登录态有效，再请求上课啦课程接口，把返回课程转换成 FakeUp 的课表结构。

如果登录态失效，接口会返回“请先登录上课啦账号”或“请重新登录上课啦账号”。

### 密令签到

提交密令时，前端会做三件事：

1. 获取浏览器定位，拿到经纬度。
2. 调用官方阿里验证码 SDK，生成一次性的 `captchaVerifyParam`。
3. 把密令、定位、`captchaVerifyParam` 提交到本站后端 `/api/signin/submit`。

后端收到请求后，会再次确认当前会话对应的上课啦登录态，并请求上课啦用户信息接口解析用户 ID。最后后端带着上课啦 token、密令、定位和官方验证码参数，调用上课啦正式签到接口 `/api/ali-nvc/captcha-verify`。

也就是说，验证码参数不是后端伪造的，仍由官方 SDK 在前端产生；签到结果也来自上课啦接口返回。

### 定位

定位由浏览器 `navigator.geolocation` 提供。手机浏览器隔一段时间后第一次定位可能会冷启动，所以页面可能先显示“仍在获取，可先提交”。如果系统随后返回定位，页面会更新为当前经纬度和精度。

### 安全边界

这个功能适合自己或熟人小范围使用。部署者需要理解：

- 后端会保存用于刷新上课啦登录态的信息，应保护好服务器和数据目录。
- 不要把服务开放给不可信用户。
- 不要尝试绕过验证码、定位或上课啦接口限制。
- 如果上课啦接口、SSO 页面或验证码策略变化，签到功能可能需要更新。

## 后端部署

上课啦相关接口由 `server/skl-proxy.mjs` 提供。Nginx 需要把 `/api/signin/` 反代到该服务。示例配置见：

- `deploy/nginx-signin-location.conf`
- `deploy/fakeup-skl-proxy.service`

## 开发

本项目主要是静态前端，加一个上课啦后端代理：

- `index.html`：页面结构
- `styles.css`：页面样式
- `app.js`：课表、背景、导出图片、签到交互
- `server/skl-proxy.mjs`：上课啦登录态、课表同步、签到代理
- `sw.js`：PWA 缓存
